# System Overview
- **Architecture**: Monolith (FastAPI) with Serverless support (AWS Lambda via Mangum).
- **Tech Stack**:
    - **Language**: Python 3.12+
    - **Framework**: FastAPI (API Gateway), Mangum (Lambda Adapter).
    - **Real-time Voice**: [LiveKit](https://livekit.io/) (WebRTC, STT, LLM, TTS orchestration).
    - **Database**: AWS DynamoDB (Primary storage for Users, Sessions, and Turns).
    - **Authentication**: JWT (JSON Web Tokens) with Email/Password (Argon2) and Google OAuth2 support.
    - **Evaluation**: LLM-based session evaluation (Google Gemini, AWS Bedrock).
    - **Storage**: AWS S3 (Session recordings and logs).

# Folder Structure
- `src/app/main.py`: Application entry point, API route definitions, and global middleware configuration.
- `src/app/auth/`: Core authentication logic, JWT utility functions, and Google OAuth integration.
- `src/app/services/`: Business logic layer; `session_service.py` coordinates DynamoDB operations and LiveKit room orchestration.
- `src/app/livekit/`: Logic for real-time voice agents, including STT/TTS configuration and conversation handling.
- `src/app/db/`: Database client implementations (DynamoDB via Boto3, SQLite for local/testing).
- `src/app/eval/`: Evaluation worker that processes session transcripts using DeepEval and LLMs to generate scores.
- `src/app/config.py`: Environment-based settings and validation using `python-dotenv`.
- `src/app/curricula/`: Management of learning modules and persona metadata.

# Key Flows

### Auth Flow
1. **Registration/Login**: User provides credentials → `user_store.py` (Argon2 hashing for passwords) → Stores/Verifies in DynamoDB → Generates and returns a signed JWT.
2. **Protected Routes**: Client sends JWT in `Authorization: Bearer <token>` header → FastAPI decodes/validates JWT → `user_id` is extracted for request context.

### Session Lifecycle
1. **Start Session**: 
   - Client calls `POST /sessions/start` with a `persona`.
   - `session_service.py` creates a new session entry in DynamoDB.
   - Generates a unique LiveKit room and a room `AccessToken`.
   - Returns room details and token to the client.
2. **Interactive Phase**:
   - Client connects to LiveKit cloud/server.
   - A Voice Agent (running via LiveKit orchestration) joins the room.
   - Agent records turns (transcripts) into the DynamoDB `turns` table in real-time.
3. **Finalization**:
   - `POST /sessions/{id}/finalize` is triggered (either by client or agent).
   - Backend fetches all turns for the session.
   - `eval_worker` sends transcripts to an LLM (Gemini/Bedrock) for qualitative and quantitative analysis.
   - Summary and scores are updated in the DynamoDB `sessions` table.

# Data Layer
- **AWS DynamoDB**: Main persistence layer.
    - `users`: User profiles, hashed credentials, and metadata.
    - `sessions`: Session state, scores, summaries, and recording links.
    - `turns`: Granular conversation data (user transcript, agent reply, token usage, timing).
    - `learning_modules`: Persona definitions, roles, and course content.
- **AWS S3**: Used for storing audio recordings from sessions (via LiveKit Egress).
- **SQLite**: Available as a local alternative for development and offline testing.

# Patterns
- **Middleware-based Handling**: CORS and Authentication are handled via FastAPI middleware and dependency injection.
- **Service Layer Abstraction**: API routes remain thin; business logic is encapsulated in the `services/` directory to ensure reusability and testability.
- **Lazy Settings**: Configuration is managed via an `@lru_cache` settings pattern, ensuring environment variables are validated at startup.
- **Token-based Orchestration**: LiveKit access is strictly controlled via short-lived JWTs generated by the backend.

# Constraints
- **Multi-tenant**: Strict isolation of session and user data via `user_id` partition keys in DynamoDB and JWT validation.
- **Low Latency**: Voice interaction requires <500ms response times; architectural choices like LiveKit and optimized LLM prompts are used to meet this.
- **High Concurrency**: Designed for serverless scaling (AWS Lambda) and distributed real-time handling (LiveKit).
- **Cost Sensitive**: Tracks token usage and estimated USD cost per conversation turn.
